# STRUKTURA CRM 1.13.9 — контроль качества финансового прогноза

## Исправлено
- `isoDate()` проверяет реальную календарную дату, а не только шаблон строки.
- Невозможная дата окончания объекта не включает долг клиента в прогноз по срокам; невозможная дата расхода не включает его в прогноз по срокам.
- Такие записи добавляют понятные предупреждения в финансовом разделе.
- Некорректные и отрицательные суммы по договору/расходам не могут превратить агрегаты в `NaN`; для вычисления используется 0 ₽ и показывается предупреждение.
- Отрицательный денежный остаток не запрещён, поскольку он может отражать реальный дефицит денег.

## Проверки, выполненные в текущем окружении
- `npm test`: 113/113 тестов пройдены.
- `node --check` для всех `src/*.js`, `src/*.cjs`, `tests/*.cjs`: успешно.
- `python3 scripts/verify-schema.py`: PASS; 14 таблиц, ограничения и сохранение после повторного открытия SQLite проверены.

## Ограничения
- Не выполнялись запуск Electron GUI на Windows, сборка/установка `.exe`, реальная проверка системных уведомлений и визуальная проверка PDF на Windows.
- Проверка качества данных выполняется для расчёта прогноза; исходные записи автоматически не исправляются и должны быть поправлены пользователем.
- Финансовый прогноз остаётся ориентиром на основе введённых дат и учёта, а не гарантией поступления денег.

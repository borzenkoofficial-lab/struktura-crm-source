# СКОЛ CRM — автономное лицензирование

## Цель

Добавить в Windows-приложение СКОЛ CRM автономную систему лицензирования. Покупатель вводит ключ в программе; приложение без интернета проверяет подпись, тариф и привязку к компьютеру, сохраняет лицензию локально и открывает только разрешённые модули.

## Принятые решения

- Целевая платформа: Windows 10/11, Electron 35, Node.js 22.
- Лицензирование полностью офлайн; никаких сетевых запросов при активации и проверке.
- Ключ — подписанный Ed25519 токен формата `SKOL1.<payload-base64url>.<signature-base64url>`.
- Закрытый ключ подписи хранится только у владельца продукта, вне репозитория и установщика.
- Открытый ключ проверки входит в установщик СКОЛ.
- Подписываемый payload содержит product, licenseId, edition, feature IDs, deviceId, issuedAt, expiresAt, updatesUntil, seatIndex и seatCount.
- Лицензия привязывается к хешу Windows MachineGuid. Покупатель передаёт Device ID продавцу при заказе; продавец выпускает ключ для конкретного устройства.
- Для нескольких компьютеров выпускаются отдельные ключи с общим licenseId и разными deviceId/seatIndex. Офлайн-программа не может централизованно подсчитать одновременные активации.
- Основной коммерческий вариант: бессрочное право использования приобретённой версии; updatesUntil хранится как срок права на обновления, но не блокирует уже установленную программу.
- START — базовые клиенты, заявки, объекты и задачи. PRO добавляет финансы, производство, расчёт объекта и отчёты. BUSINESS добавляет центр заказов, браузер, инженерные планы и расширенную аналитику.
- Лицензия хранится в существующей таблице settings SQLite; существующие данные и путь к БД не меняются.
- Никакие секретные ключи, тестовые приватные ключи или реальные ключи покупателей не коммитятся.

## Тарифные разрешения

- START: базовые разделы; без дополнительных feature-gated каналов.
- PRO: finance, production, engineering, reports.
- BUSINESS: все возможности PRO плюс engineering_plans, order_radar, web_browser, advanced_analytics.

## Потоки

### Выпуск
1. Продавец получает Device ID от покупателя.
2. Локальный генератор лицензий принимает тариф, Device ID и срок обновлений.
3. Генератор подписывает payload закрытым ключом.
4. Продавец передаёт покупателю строку ключа.

### Активация
1. Приложение показывает Device ID и поле ключа.
2. Покупатель вставляет ключ.
3. Main process проверяет подпись открытым ключом, структуру, продукт, тариф, срок и совпадение Device ID.
4. Подписанный токен сохраняется в SQLite settings.
5. Приложение разрешает запуск рабочих модулей.

### Офлайн-запуск
1. Main process повторно проверяет сохранённый токен локально.
2. Центральная IPC-обёртка запрещает защищённые операции, если лицензия отсутствует или недействительна.
3. IPC-обёртка проверяет feature ID для каналов PRO/BUSINESS.
4. Renderer скрывает недоступные пункты навигации и показывает статус тарифа.

## Безопасность и ограничения

- Не использовать общий секрет/HMAC, зашитый в клиент.
- Не хранить закрытый ключ в src, package, installer, GitHub Actions или приложении.
- Проверка тарифа выполняется в main process, не только в renderer.
- Device ID формируется как SHA-256 от нормализованного MachineGuid с доменным префиксом продукта; исходный MachineGuid не отображается и не сохраняется.
- Офлайн-система не умеет удалённо отзывать лицензию, подтверждать оплату или гарантированно выявлять клонирование Windows MachineGuid.
- Перенос лицензии на другой компьютер требует выпуска нового ключа для нового Device ID.
- Ошибки активации не должны удалять пользовательскую базу или мешать резервному копированию данных.

## Вне объёма первой версии

- Интернет-магазин и платёжный шлюз.
- Онлайн-личный кабинет клиента.
- Удалённый отзыв лицензий.
- Автоматическая синхронизация количества устройств.
- Подписочная проверка через сервер.
- Отдельный GUI License Manager; на первом этапе выпускается автономный CLI-генератор.

## Критерии приёмки

- Валидный ключ активирует указанный тариф на совпадающем устройстве.
- Подделанный, повреждённый, просроченный, чужой продукт или ключ для другого Device ID отклоняется.
- START не выполняет IPC-операции PRO/BUSINESS.
- PRO не выполняет IPC-операции BUSINESS.
- Доступы проверяются в main process.
- Программа запускается и работает после активации без интернета.
- Существующие пользовательские данные сохраняются.
- Генератор не включает приватный ключ в дистрибутив.
- Все тесты и CI Windows build проходят.

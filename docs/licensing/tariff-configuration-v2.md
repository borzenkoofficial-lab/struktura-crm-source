# Настройка тарифов СКОЛ CRM

Версия 1.25.0 добавляет конструктор тарифов и лицензии формата v2. Старые подписанные лицензии v1 (START / PRO / BUSINESS) продолжают проверяться.

## Feature ID — только реальные разделы CRM

- `finance` — финансы и платежи.
- `production` — производство и ПИ.
- `engineering` — инженерный расчёт.
- `reports` — отчёты.
- `order_radar` — радар заказов.
- `web_browser` — встроенный браузер.
- `engineering_plans` — инженерные планы.

`advanced_analytics` остаётся только для проверки старых лицензий v1. Для новых планов он запрещён: в CRM пока нет отдельного enforcement-механизма этого модуля.

## Настройка готовых тарифов

Открой License Manager командой `npm run license-manager`. Выбери закрытый Ed25519 PEM-файл. В блоке настройки выбери план или создай новый, укажи ID, название, описание, цену в RUB (или оставь пустой), предел компьютеров от 1 до 50 и отметь feature ID. Неизвестные ID и некорректные значения отклоняются.

Нажми «Экспорт JSON». Файл имеет формат `SKOL_TARIFF_CONFIG`, содержит `schemaVersion`, `catalogVersion`, `featureIds` и `plans`. Для публикации на сайте замени `public/skol-tariff-config.json` в репозитории SKOL-SITE этим файлом и опубликуй сайт.

## Индивидуальная заявка с сайта

На странице `/tariffs` клиент выбирает готовый тариф или отдельные модули. Сайт формирует `SKOL_LICENSE_REQUEST` с выбранными feature ID, ID/названием плана, контактами и числом компьютеров. Клиент скачивает JSON-заявку.

В License Manager выбери «Загрузить заявку JSON», проверь запрос и Device ID, затем выпусти ключ. Менеджер проверяет каталог и подписывает выбранные разрешения локальным закрытым ключом. Сайт не подписывает ключи и не получает закрытый ключ.

## Формат v2

Внешний формат токена остаётся `SKOL1.<payload>.<signature>`. Подписанный payload v2 включает `planId`, `planName`, `features`, `deviceId`, сроки, `seatIndex` и `seatCount`. CRM проверяет Ed25519, устройство, срок и разрешения; защищённые операции ограничиваются в Electron main process, а не только скрытием пунктов меню.

## Важные ограничения

- Цена из конфигурации — справочное значение для тарифной витрины, а не подтверждение оплаты. Серверной оплаты и автоматической доставки заявок нет.
- Число мест в офлайн-режиме нельзя централизованно проверить между разными компьютерами. Для каждого Device ID выпускается отдельный ключ; `maxDevices` ограничивает выпуск внутри одной заявки/плана, а не создаёт глобальный серверный счётчик.
- Офлайн-ключ нельзя удалённо отозвать. Замена компьютера требует нового ключа.
- `updatesUntil` хранится и отображается, но в этой версии не прекращает работу программы после указанной даты.
- Закрытый ключ хранится отдельно, не коммитится, не включается в сайт, клиентскую CRM или установщик.

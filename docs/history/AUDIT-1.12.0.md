# STRUKTURA CRM 1.12.0 — аудит производственной модели

**Статус:** исходники обновлены, статические проверки и модульные тесты пройдены. Реальный запуск Electron и сборка Windows-инсталлятора не подтверждены в текущей среде.

## Что реализовано

### 1. Производственный контур
- В боковую навигацию добавлен раздел «Производство».
- Для объектов со статусом «В работе» показываются производственный план, факт по каждому виду работы, остаток объёма, число записанных смен, человеко-смены и дата последнего отчёта.
- План можно создать/изменить отдельно. При создании объекта непосредственно из сметы производственный план и объект сохраняются одной транзакцией SQLite.
- Прогноз рассчитывается по оставшемуся объёму с учётом плановой численности бригады, сложности объекта и нормы по каждому виду работ.

### 2. Отчётность по сменам
- Сохраняются дата, численность всей бригады, продолжительность смены, простой, коэффициент сложности и примечание.
- Для каждого вида работ фиксируются объём, фактически занятые люди, часы именно на эту работу, единица измерения и стартовая норма, действовавшая для отчёта.
- Отчёт без выработки допустим только при наличии причины в примечании. Такой отчёт остаётся в истории и учитывает факт присутствия людей, но не создаёт фиктивный объём для обучения.
- История хранит до 50 последних отчётов в интерфейсе. Ошибочный отчёт можно удалить; связанные строки удаляются по внешнему ключу, поэтому отчёт исключается из расчёта производительности.

### 3. Статистическая корректировка норм
Для каждого вида работ производительность нормализуется к обычным условиям:

`объём / (занятые люди × часы / 8) × коэффициент сложности`

Модель использует медиану фактических наблюдений, чтобы единичное очень высокое значение меньше искажало оценку. Затем нормализованная медиана смешивается со стартовой нормой:

| Наблюдения по одному виду работ | Вес практики | Вес стартовой нормы |
|---|---:|---:|
| Нет | 0% | 100% |
| 1–2 | 25% | 75% |
| 3–4 | 50% | 50% |
| 5 и более | 75% | 25% |

Новый прогноз отображает статус уверенности по каждому виду работ. Сырые данные смен сохраняются локально; накопленная статистика влияет и на текущие объекты, и на калькулятор предварительной сметы. При наличии как минимум пяти наблюдений и повторных измерений минимум на двух размерах рабочей группы модель оценивает логарифмическую зависимость выработки на человека от численности; коэффициент ограничен, чтобы единичные данные не вызывали чрезмерной экстраполяции. Если данные не подходят, модель сохраняет линейное предположение. Это воспроизводимый статистический алгоритм, не ИИ и не гарантия срока. Количество наблюдений считается отдельно по каждому `catalog_id`, а не по объекту в целом.

### 4. Проверки данных
- От 1 до 200 человек в бригаде; длительность смены 0,5–24 часа; простой не выше длины смены.
- Коэффициент сложности берётся из заданного набора.
- В плане и отчёте не допускаются повторяющиеся виды работ.
- Распределённые по строкам человеко-часы не могут превышать `численность всей бригады × длительность смены`.
- Пустая смена требует примечания.
- Объект и производственный план из сметы создаются атомарно.

## Что не подтверждено

- В этой среде не установлены `electron`, `better-sqlite3`, Playwright и jsdom. Поэтому настоящее окно приложения, реальную SQLite-интеграцию именно через Node/Electron, взаимодействие с установленной базой старой версии и Windows `.exe` не запускали.
- Проверка схемы через `scripts/verify-schema.py` — отдельный тест SQLite-сценариев, не подмена реального Electron smoke-test.
- Срок является оценкой. Он может быть оптимистичным при простоях, ограничениях доступа, логистических потерях и параллельных/последовательных зависимостях между работами. Простой записывается, но текущая выработка по работе рассчитывается по указанным трудозатратам именно на эту работу. Поправка на размер бригады включается только при достаточной истории по одному виду работ и нескольким размерам групп; без таких данных эффективность линейно масштабируется по численности.
- Практику нужно записывать последовательно. Пять отчётов по одному виду работ дают ему больше веса; один отчёт по пяти разным работам не даёт сильной уверенности для всех пяти.

## Как начать вести данные

1. Создать объект и перевести его в статус «В работе».
2. В разделе «Производство» заполнить полный план работ.
3. После каждой смены записывать фактический объём, число работников по каждой работе и затраченное на неё время.
4. Сверять показанное отклонение и исправлять явные ошибки в данных до того, как принимать решение по сроку.
5. Перед заменой установленной программы обязательно сохранить резервную копию локальной базы.
